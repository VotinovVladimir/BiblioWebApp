2.2. Объект и предмет
Объект: процессы библиотечного учёта.

Предмет: автоматизация учёта читателей, книг и выдачи средствами web-приложения и реляционной БД.

2.3. Роли пользователей
Для минимального объёма (без аутентификации) роль одна — библиотекарь (оператор), который:

ведёт справочник книг и читателей;

оформляет выдачу и возврат;

формирует отчёты.

Если руководитель потребует аутентификацию — добавляется роль «читатель» с просмотром своих книг; это фиксируется в день 7–9 как расширение.

2.6. Use cases (сценарии использования)
UC-1. Добавление книги

Актор: библиотекарь.

Шаги: «Книги» → «Добавить» → заполнить поля → «Сохранить».

Результат: книга в списке, доступна для выдачи.

Исключение: дубликат инвентарного номера → сообщение об ошибке.

UC-2. Добавление читателя

Шаги: «Читатели» → «Добавить» → заполнить → «Сохранить».

Исключение: дубликат номера билета → ошибка.

UC-3. Выдача книги

Шаги: «Выдачи» → «Оформить выдачу» → выбрать читателя → выбрать доступную книгу → дата выдачи и срок → «Сохранить».

Результат: книга помечена как выданная, в карточке читателя +1.

Исключение: книга недоступна → отказ с сообщением.

UC-4. Возврат книги

Шаги: «Выдачи» → найти активную выдачу → «Вернуть».

Результат: статус «возвращена», книга снова доступна, в карточке читателя −1.

UC-5. Просмотр карточки читателя

Шаги: «Читатели» → выбрать читателя.

Результат: ФИО, билет, контакты, список книг на руках, количество.

UC-6. Отчёт «Книги на руках у читателя»

Шаги: «Отчёты» → «Книги на руках у читателя» → выбрать читателя.

Результат: список активных выдач (книга, дата выдачи, срок).

UC-7. Отчёт «Количество книг на руках у читателей»

Шаги: «Отчёты» → «Количество книг на руках».

Результат: таблица «читатель — количество», включая читателей с 0.

UC-8. Поиск книги

Шаги: «Книги» → ввести строку в поиск.

Результат: отфильтрованный список.

2.7. Перечень отчётов и запросов к БД (связь с ТЗ)
Отчёт	Что показывает	Тип запроса
Сведения о читателях	Список читателей с контактами	SELECT из readers
Сведения о книгах	Список книг с автором, жанром, доступностью	SELECT + JOIN genres
Книги на руках у читателя	Активные выдачи выбранного читателя	JOIN loans–books–readers WHERE return_date IS NULL
Количество книг на руках у читателей	Читатель → количество	LEFT JOIN loans + GROUP BY reader + COUNT
Это прямое покрытие требования ТЗ: «БД должна обеспечивать получение сведений о читателях, книгах, количестве книг на руках у читателей».

2.9. Критерии приёмки
Проект считается выполненным, если:

□ Приложение запускается по инструкции на чистом окружении.
□ В браузере доступны: список книг, список читателей, карточка читателя, выдача, возврат, два отчёта.
□ БД содержит ≥4 связанных таблицы, связи — внешними ключами.
□ Отчёт «количество книг на руках» корректен, включая читателей с 0.
□ Невозможные операции (выдача занятой книги, удаление читателя с книгами) блокируются.
□ ПЗ содержит все 10 разделов и оформлена по ГОСТ.
